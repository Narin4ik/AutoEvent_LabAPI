# Авто-ивенты в Narin4ik/AutoEvent_LabAPI

Это дополнение к LabAPI-версии MedveMarci. Система находится в `AutoEvent.dll`:
модули `AutoEvent.AutoRun` и `AutoEvent.Vote` для неё не нужны.

## Установка

Установите зависимости из [инструкции](Installation.md), замените `AutoEvent.dll`
на DLL этого форка и перезапустите сервер. Если используете дополнительные модули,
замените их DLL версиями из того же архива: они учитывают занятость автоцепочки.
Нужна серверная команда `scpstats disable` / `scpstats enable`, которая возвращает
успешный результат выполнения. Без неё автоматическая цепочка отменяется.

В `permissions.yml` выдайте администраторам `ev.auto` либо `ev.*`.
Проверьте схемы командой `ev list`, затем `ev run <name>`.

## Как работает цепочка

1. Счётчик учитывает начатые серверные раунды с момента загрузки плагина.
   Перед раундами **4, 8, 12…** начало раунда блокируется на **45 секунд**.
2. Игроки открывают Server Specific Settings → «Авто-ивенты» и нажимают «Да» или «Нет».
   Один игрок имеет один голос, противоположная кнопка меняет выбор, выход удаляет голос.
   При **Да > Нет** начинается цепочка; ничья и отсутствие голосов дают обычный раунд.
3. Через 2 секунды после старта раунда отключается SCPStats и запускается случайная игра.
   Тюрьма (`jail`) никогда не выбирается. Nuke Run (`nukerun`) зарезервирован для финала.
   Схемы, зависимости и ограничения количества игроков проверяются перед выбором.
4. После полной очистки игры участники получают роль лобби и начинается новое
   45-секундное голосование «Продолжить авто-ивенты?». Завершение раунда заблокировано.
5. Для продолжения нужно **не менее 65% среди проголосовавших**:
   `100 × Да >= 65 × (Да + Нет)`. Не голосовавшие не учитываются.
   13 из 20 — продолжение; 9 из 14 (около 64,29%) — завершение.
6. При успехе выбирается следующая случайная игра без повторов в этой цепочке.
   После неё голосование повторяется. При результате ниже 65%, отсутствии голосов
   или исчерпании доступных игр запускается финальный Nuke Run.
7. После полной очистки Nuke Run раунд перезапускается один раз. Нового голосования
   после Nuke Run нет. В следующем ожидании игроков восстанавливается SCPStats.

Статистика отключена на всю цепочку, включая промежуточные голосования и Nuke Run.
Ручные мини-игры и отдельный непрерывный AutoRun статистику этим механизмом не отключают.
При ошибке первой игры статистика восстанавливается сразу после обнаружения ошибки;
при ошибке последующей игры раунд перезапускается. Выгрузка плагина также восстанавливает
статистику. Неудачная попытка восстановления сохраняется для следующего лобби/выгрузки
и явно записывается в журнал.

## Команды

| Команда | Действие |
| --- | --- |
| `ev auto status` | Счётчик раундов, этап цепочки, голоса и состояние восстановления SCPStats |
| `ev auto on` | Включить периодические голосования |
| `ev auto off` | Отключить голосования и отменить продолжение цепочки |
| `ev auto reset` | Обнулить счётчик и отменить голосование/продолжение |

`off` и `reset` не обрывают текущую игру: освобождение блокировки происходит после её
очистки. Ручная остановка случайной игры через `ev stop` также отменяет цепочку.
При административной отмене принудительного Nuke Run и перезапуска нет.
Включение/выключение командами действует до перезагрузки плагина.

Для совместимости **непрерывный AutoRun перенесён под `ev loop start|stop|status`**
(право `ev.auto` сохранено). Активный AutoRun или Vote подавляет периодическое
голосование. Их запуск отменяет ещё не начавшуюся периодическую цепочку, но отклоняется,
если цепочка уже владеет раундом. Перед ручным запуском во время цепочки используйте
`ev auto off` и дождитесь очистки текущей игры.

## Конфигурация

Раздел `auto_voting` добавляется в основной конфиг AutoEvent в LabAPI.
Изменения применяйте с перезапуском плагина/сервера.

```yaml
auto_voting:
  enabled: true
  round_interval: 4
  vote_duration_seconds: 45
  broadcast_interval_seconds: 1
  broadcast_duration_seconds: 1.5
  excluded_events: []
```

Тексты настраиваются полями `vote_broadcast_text`, `vote_passed_text`, `vote_failed_text`,
`continue_broadcast_text`, `continue_passed_text`, `continue_failed_text`.
Подстановки сообщений голосования: `{time}`, `{yes}`, `{no}`, `{percent}`.
Названия кнопок и подсказки: `settings_group_name`, `yes_label`, `yes_button_text`,
`yes_hint`, `no_label`, `no_button_text`, `no_hint`.
Порог продолжения фиксирован на 65%. `excluded_events` содержит команды игр либо их
имена; исключения не могут разрешить тюрьму или случайный Nuke Run.

Длительность броадкаста в игровом API целочисленная: 1,5 секунды передаются как 2,
а сообщение очищается по таймеру через 1,5 секунды, если его не сменило следующее
сообщение голосования. Идентификаторы настроек: 6102410–6102412. Конфликт с другим
плагином блокирует включение голосования и записывается в журнал.

## Сборка и проверка

.NET SDK 10; основные плагины собираются под .NET Framework 4.8, LabAPI 1.1.7.
Укажите `SL_REFERENCES` (игровые DLL), `LABAPI_PLUGINS` и `LABAPI_DEPENDENCIES`.
Проверенные зависимости: ProjectMER 2026.7.6.1, RadioMenuAPI 1.4.0,
LabApiExtensions release-v0.3.0; остальные версии закреплены в проектах.

```powershell
dotnet build AutoEvent.sln -c Release -p:CI=true
dotnet run --project Tests/AutoEvent.Automatic.Tests.csproj -c Release
```

`CI=true` отключает автоматическое копирование DLL в локальную папку сервера.
Тесты проверяют правила, точный порог, отсутствие повторов, переходы контроллера,
отмену таймеров и ошибки SCPStats в детерминированной симуляции серверного API.
Они не заменяют проверку загрузки DLL и игрового процесса на настоящем SCP:SL-сервере.
